# 플레이북 "바둑" 운영설계 (7/4) — 경우의 수 관측 체계

> 사장님 7/4 지시: "장 시작 전 뭘 봐야 하는지 → 그걸 약간의 토대로, 장중
> 이미 오르는 종목 추가상승 추매 / 상한가 엔진 / 소문에 사서 뉴스에 팔기 /
> 뉴스에 사서 개미 유입에 팔기 — 여러 경우의 수를 바둑처럼 유연하게."
>
> 원칙: 전부 record-only 관측 먼저 → forward 성적 → 사장님 승인 → 라이브.
> 관측 없이 flip 금지. 봇 OFF·실주문 0 불변.

## 1. 프레임 — 정석(플레이북) × 정찰(아침 브리핑) × 기보(페이퍼 장부)

```
[저녁 nightly]                          [아침]                [장중 (미래·설계)]
⑰ 레짐(회피신호+지수정배열) ─┐
③-4 테마릴레이(바통 단계)   ─┤→ ⑱ 아침브리핑 한 장 → 오늘 우선 볼 정석 선택
⑪ 명분끼(소문/뉴스 단계)    ─┤   (+ 08:45 오픈게이트     → 해당 플레이북 관측
⑯ 클러스터 pending          ─┘      오버레이)               (지금은 ⑲ 사후 replay)
⑲ 플레이북 페이퍼(기보 축적) — 어제까지의 수를 복기
```

## 3. 정직한 한계 (해석 의무)

- ⑲ replay 해상도 = **~20분 관측 간격**. 진입은 신호 "다음 관측행" 실측가(보수),
  같은 행 TP/SL 동시성립은 SL 우선(보수). 윈도우 내부 경로 가정 0.
- 레짐 게이트는 **회피 전용** 검증(7/4 레짐검증 63일) — GO는 상승예측 아님.
- 소문매수 신호 5일간 0건 발화 = catalyst 후보풀이 이미 오른 종목이라 맥점(초입)
  조건과 구조적으로 상충 — 후보풀 확장(선행 next_candidates 쪽) 검토 과제.
