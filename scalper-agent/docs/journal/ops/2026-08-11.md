## §2. 발견 — 수급 채널에 "거래 없는 날의 행"이 쌓이고 있었다 ([F-162])

점검 통과가 결론인데, 그 과정에서 딸려 나왔다.

### 실측

- `investor` 행은 있으나 매매 **수량·금액 전부 0**인 (날짜,종목) = **7,138쌍**
- 그중 종가(daily)에도 행이 없어 **양 채널이 독립적으로 '거래 없음'에 동의**하는 strict = **1,387쌍** (5/27~8/11)

### 근본은 우리 코드가 아니다 (의심했고, 확인했고, 기각했다)

`_fetch_investor_api`는 KIS `output`에 있는 행만 append 하고, 병합은
`pd.concat([old, df])` + dedup(keep=last) + sort 로 **forward-fill 이 없다**(`flow_collector.py:289-291`).
→ **KIS가 정지 종목에 기준가 + 플로우 0 행을 준다.** 원본 충실이므로 수집기를 고치는 것은 오답이고,
문제는 **소비자가 "행이 있다"를 "그날 거래했다"로 읽는 것**이다.

### 사정권 — (날짜,종목) **쌍** 대조 (8/6 [F-123] 확립 방법)

종목 단위 교집합은 *"언젠가 신호난 종목"*을 잡을 뿐 *"박제된 날의 신호"*가 아니다. 반드시 날짜를 맞춘다.

| `observe_v2_paper_ledger` (**라이브 후보 PB-A v2**) | 1,306 | **0건** |
| `playbook_shadow` (PB-B) | 79 | **1건** |
| `institution_accum_scan` | 82 | **1건** ([F-163]) |

**라이브 후보가 0건인 것은 운이 아니라 게이트다** — PB-A v2의 **체결강도 200+** 조건이 strength=0을

### ③ 하지 않은 검증을 했다고 출력했다 (오늘 최악)

수집 창 밖에서 재려고 `pgrep -f`로 프로세스 부재를 기다리는 가드를 걸었다. 그런데
**패턴 문자열이 내 명령줄에 들어 있어 pgrep이 자기 자신을 셌다**(재현 확인: 이미 종료된 nightly
패턴이 2건으로 잡힘). 조건은 **한 번도 참이 된 적이 없고**, 루프가 90회를 다 돌고 시간 초과로
빠져나왔다(18:46 + 90×40초 = **19:46** — 출력 시각과 정확히 일치).

더 나쁜 것은 그 다음이다. 출력에 `(대기 프로세스 0 확인)`이라 찍혀 있었는데,
**그 문구는 조건과 무관하게 무조건 나오는 라벨**이었다. 그래서 62.2%라는 **수집 도중 수치**를
"창 밖에서 쟀다"며 사장님께 보고했다.

fix = 프로세스 부재 대신 **로그의 완료 표식**을 grep(파일을 보므로 자기매치가 원천 불가) +
잔여 프로세스는 **별도로 세어 출력**(판정 근거가 아니라 참고로 명시). 재실행 결과 `ok=1`·잔여 0.

**② 미흡**

겪고도 내가 새로 짠 가드에는 같은 검사를 적용하지 않았다. 더 나쁜 건 출력 라벨이

**③ 교훈 → 메모리**
**"확인했다"고 출력하는 문장은 그 확인의 결과값을 반드시 인쇄해야 한다.**
`(대기 프로세스 0 확인)`이 아니라 `ok=1 / 잔여 0`처럼 **측정값 자체**를 찍었다면 그 자리에서 틀린 걸

**④ 내일 적용 1가지**
내가 새로 쓰는 모든 대기/가드 루프에 **음성 대조를 먼저 건다** — "이 조건이 거짓일 때 정말

### [F-160] — 문구를 고치지 않고 **숫자를 없앴다**

같은 임계가 세 곳에서 다른 값을 말했다: docstring `"24h+"` · 인라인 주석 `"24시간 이상"` ·
코드 `> 48`. 문구만 48로 맞추는 것은 **반쪽 fix** 다 — 숫자가 두 곳에 남으면 다음에 또 어긋난다.

fix = `NIGHTWATCH_STALE_HOURS = 48` 모듈 상수 1개. 비교식이 상수를 참조하고,
**docstring 은 숫자를 적지 않고 상수 이름을 가리킨다.** [F-158] 주석의 `48h` 도 정리.

**행동은 바꾸지 않았다.** 주말 구조적 폴백(금요일분이 월요일에 72h → 매주 월요일 사실상
'안정')은 **사실로 등재만** 한다. 임계 변경은 매매 동작을 바꾸므로 사장님 결정 사안이고,
레짐 SL 이 룰보다 조여지던 위험은 [F-158] 하한으로 이미 차단돼 있다.

**검증**: `tests/test_macro_stale_threshold_8_11.py` **9/9** (AST 기반) ·
저장소 전체 `tools/run_all_tests.py` **46/46 PASS**.

★**음성 대조 3종**을 넣었고 세 번째가 핵심이다:
①구판(docstring 24h + 코드 48) 검출 ②**문구만 맞춘 반쪽 fix 도 검출** ③**모듈 주석의 옛 문구
인용은 위반이 아님**을 고정. ③이 없었다면 파일 전체 grep 검사기가 **사고 경위를 적은 내 주석을
위반으로 세어 옳은 코드에 FAIL** 을 냈을 것이다 — **오늘 네 번째 자기참조 계수**가 될 뻔했고,
이번엔 짜기 전에 알아채고 사정권을 `ast.get_docstring` + 비교식 노드로 좁혔다.
