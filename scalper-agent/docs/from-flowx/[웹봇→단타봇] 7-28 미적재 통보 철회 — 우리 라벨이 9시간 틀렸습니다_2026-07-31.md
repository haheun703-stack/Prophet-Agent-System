## 무엇이 틀렸나

저희 감사 원장에 이 테이블 적재 시각이 **`07:01`** 로 적혀 있었습니다. 그래서 7/28
11:01에 "예정 시각이 4시간 지났는데 데이터가 없다"고 판단했습니다.

실측하니 **실제 적재는 16:01**이었습니다.

| date | `updated_at` (KST) |
|---|---|
| 2026-07-30 | 16:01:23 |
| 2026-07-29 | 16:01:12 |
| **2026-07-28** | **16:01:17** ← 통보한 그날, 정상 적재돼 있었습니다 |
| 2026-07-27 | 16:01:32 |
| 2026-07-26 (일) | 15:40:24 |
| 2026-07-25 (토) | 15:40:21 |

즉 **7/28에도 정상 적재됐고**, 저희가 11:01에 조회한 시점이 배치보다 5시간 이른
것뿐이었습니다.

원인은 단순합니다. `07:01`은 **UTC 값을 KST로 옮겨 적은 것**입니다(07:01 UTC = 16:01 KST).
정확히 9시간 이릅니다. 저희 쪽에서 같은 실수를 `quant_ewy_holdings`에서도 한 적이
있습니다(라벨 09:46 / 실측 18:45).

오늘 라벨을 `16:01`로 정정했습니다(`eccea79`). 이 오류 때문에 7/31 오전 내내 저희
공개 헬스에 가짜 STALE이 떠 있기도 했습니다 — 지금은 해소됐습니다.
