## 결재 1 — 읽기 전용 SSH 프로브: **허가**

웹봇은 미확정 2개 IP(`13.125.86.203` · `3.34.146.5`)에 대해 v2 §3 절차를 1회 실행하라.

- **읽기 전용만.** `hostname` 외 어떤 명령도 실행하지 않는다. 파일·설정·잡 일절 손대지 않는다.
- `BatchMode=yes`로 암호 프롬프트에서 멈추지 않게 한다.
- 결과를 v3 §3 표에 채우고, **성공/실패 조합을 전부** 기록한다(실패도 정보다).
- 웹봇 세션에서 도구 정책으로 SSH가 막히면 **우회하지 말고** 그 사실을 회신하라. 그때는 다른 봇에 위임하거나 운영자가 직접 확인한다.

## 결재 2 — 인계 방식: **A안(봇별 전용 키)** 채택

세 봇이 모두 A안을 권고했고, 근거(감사 추적·개별 회수)를 수용한다.

### 회수·발급 명단

| 봇 | 현재 상태 | A안 후 |
|---|---|---|
| 퀀트봇 | 단타봇 트리 `_tmp_zips/lightsail_60gb.pem` 사용(= 키 1과 동일 지문) | 전용 키 발급 |
| 단타봇 | 같은 키 보유(원 소재지) | 전용 키 발급 |
| 정보봇 | 같은 서버 접속 중 | 전용 키 발급 |
| 웹봇 | 키 보유하나 사용처 0건 | 필요 시 발급(미접속 유지 가능) |
| 블로그봇 | 키 2 추정 | 매핑 확정 후 판단 |

### 전환 절차 — **순서를 지킨다. 기존 키를 먼저 지우지 않는다**

1. **각 봇이 자기 키쌍을 만든다**(`ssh-keygen -t ed25519`). 개인키는 자기 쪽 저장소 **밖**에 `chmod 600`으로 둔다. 공개키만 제출한다.
2. 서버 관리자가 `~/.ssh/authorized_keys`에 **공개키를 추가만** 한다. 이 단계에서는 아무도 잠기지 않는다.
3. 각 봇이 **새 키로 접속을 검증**하고 회신한다.
4. 넷 다 검증되면 그때 **기존 공유키를 제거**한다. 검증 전 제거 금지 — 하나라도 실패하면 그 봇이 서버에서 잠긴다.
5. 원장 1줄씩 남긴다: 누구에게 · 언제 · 어느 키를. 이것이 다음 회수의 명단이 된다.

### 지금 지켜야 할 것

- **키 파일 위치를 옮기지 마라**(웹봇 v2 §3 요청 수용). 4단계 전까지는 현 위치 유지.
- 키를 git·이슈·문서·채팅에 넣지 않는다. `.gitignore`의 `*.pem`은 확장자만 막으므로 `key.txt` 같은 이름으로 바꿔 두는 것도 금지.
