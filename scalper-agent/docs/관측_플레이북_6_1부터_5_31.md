## 2. 뭘 수집/저장하나 (자동 — 내가 6/1 전 배선 완료)
- **recommendation.json**: 그날 픽 + 각 픽의 `thesis_pass`/`thesis_strong`/`thesis_buckets`/`kki_score`/`kki_grade` (5/31 저장 추가됨).
- **recommendation_history (일일 스냅샷)**: 픽별 `thesis_pass`/`kki_grade` + `T1/T2/T3/T5` forward 수익 (성과추적 인프라가 자동 채움).
- → **즉, 매일 "그날 픽 + 명분/끼 태그 + 그 픽들의 며칠 뒤 실제 수익"이 자동 저장된다.** 이게 flip 결정의 원료.

## 3. 뭘 봐야 하나 (매일 눈으로)
- 저녁 로그 2줄:
  - `[명분게이트/shadow] cutoff후 N건 중 명분통과 P건 / 미통과 M건(약신호더미 후보)` → 미통과 비율이 높으면 약픽이 많이 섞여 들어온다는 신호.
  - `[끼 관측/shadow] 등급분포 {...} | EXPLOSIVE+HUNTABLE H건` → 오늘 픽에 끼 있는 종목이 몇이나.
- 핵심 질문(눈으로 가설): **명분 미통과로 찍힌 픽이 실제로 다음날 약했나? 끼 높은 픽이 더 잘 갔나?**

## 4. 뭘 학습/검증하나 (1~2주 데이터 쌓인 뒤)
> 분석 도구(다음 빌드): `recommendation_history`를 읽어 thesis_pass·kki_grade별 T1~T3 평균수익 비교.
- **검증 A (명분게이트 유효성)**: 명분 **미통과** 픽 평균 T1~T3 < **통과** 픽 → 게이트가 약픽을 거른다 = flip 근거.
- **검증 B (끼 유효성)**: kki_grade ↑일수록 T1~T3 ↑ → 끼 랭킹 반영 근거 (오늘 백테스트와 forward 일치하는지).
- **반증 대비**: 미통과 픽이 오히려 더 잘 가면 → 게이트 임계(0.6/2) 재조정 or flip 보류. (감 아닌 데이터로)

## 5. 언제 brick5 flip 하나 (결정 기준)
**아래 전부 충족 시에만 사장님께 flip 제안:**
1. 관측 ≥ 10거래일 (표본 충분)
2. 검증 A PASS (명분 미통과 < 통과, forward 데이터)
3. 검증 B PASS (끼↑→수익↑ forward 확인)
4. 명분통과 픽 수가 TOP-N 채울 만큼 충분 (degrade 안전망 작동 확인)
→ 충족하면: 명분게이트 cutoff 적용 + 끼 랭킹 반영 + HIGH_VOLATILITY -5 모순해소 (brick5). **사장님 최종 승인 후.**
